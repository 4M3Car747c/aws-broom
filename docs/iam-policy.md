# IAM 策略 · IAM policy

[中文](#中文) · [English](#english)

策略文件位于 [`docs/iam/`](iam/)，由 [`tools/iampolicy`](../tools/iampolicy/main.go) 从当前 `go.mod` 锁定的 cloud-nuke 源码自动生成（`make iam-policy`，CI 会校验其是否过期）。逐资源类型的动作清单见 [`iam/actions.md`](iam/actions.md)。
The policy files live in [`docs/iam/`](iam/) and are generated by [`tools/iampolicy`](../tools/iampolicy/main.go) from the exact cloud-nuke revision pinned in `go.mod` (`make iam-policy`; CI fails when they are stale). The per-resource-type action list is in [`iam/actions.md`](iam/actions.md).

## 中文

### 工具会用你的凭证做什么

| 阶段 | 调用 | 说明 |
|---|---|---|
| 登录 | `sts:GetCallerIdentity` | 校验凭证、取得账号 ID 与 ARN。没有这个权限就无法登录。 |
| 选区域 | `ec2:DescribeRegions` | 列出账号已启用的区域。 |
| 扫描 | 各服务的 `List*` / `Describe*` / `Get*` | 只读。某个资源类型被拒绝时，该类型记为错误，其余类型继续。 |
| 扫描（EC2 / VPC 家族） | 带 `DryRun=true` 的删除调用 | cloud-nuke 用它检查你是否有删除权限。缺少删除权限时扫描仍成功，但这些资源会显示为"不可删除"。涉及的 23 种类型在 [`iam/actions.md`](iam/actions.md) 里标为 Dry-run。 |
| 扫描（勾选"仅清理 N 小时前创建的资源"时） | `ec2:CreateTags`、`ecs:TagResource`、`es:AddTags`、`network-firewall:TagResource`、`sns:TagResource` | 给没有创建时间的资源写 `cloud-nuke-first-seen` 标签。不勾选该选项时不会写任何标签。 |
| 清理 | 对应服务的 `Delete*` / `Terminate*` / `Detach*` 等 | 只针对你在 Review 页逐条确认的资源。 |

工具永远不会：创建资源、修改你的 IAM 策略（除非你勾选了 IAM 分组并确认删除）、把凭证写入磁盘或日志、访问实例元数据服务（IMDS）或宿主机的 `~/.aws`。

### 推荐做法：专用角色 + 一小时 STS 临时凭证

1. 在**沙箱 / PoC 账号**里创建角色 `AwsBroom`，信任你自己的 IAM 用户或 SSO 身份，并要求 MFA；`MaxSessionDuration` 保持默认 1 小时：

   ```json
   {
     "Version": "2012-10-17",
     "Statement": [{
       "Effect": "Allow",
       "Principal": { "AWS": "arn:aws:iam::123456789012:user/you" },
       "Action": "sts:AssumeRole",
       "Condition": { "Bool": { "aws:MultiFactorAuthPresent": "true" } }
     }]
   }
   ```

2. 按下文"三档权限"给角色附加策略。
3. 取得临时凭证并粘贴到页面（Access Key 以 `ASIA` 开头，Session Token 必填）：

   ```sh
   aws sts assume-role \
     --role-arn arn:aws:iam::123456789012:role/AwsBroom \
     --role-session-name broom \
     --duration-seconds 3600 \
     --query 'Credentials.[AccessKeyId,SecretAccessKey,SessionToken]' --output text
   ```

页面上给出的 `aws sts get-session-token` 也可以用，但它继承 IAM 用户的**全部**权限、无法收窄，策略要直接附加到该用户上。请勿使用长期 Access Key，更不要使用 root 凭证。

### 三档权限

| 档位 | 用途 | 使用方式 |
|---|---|---|
| **只读** | 只扫描、导出清单，不清理 | [`iam/scan.json`](iam/scan.json)。它约 7500 字符，超过托管策略 6144 字符上限，请作为**内联策略**附加（角色内联上限 10240）：`aws iam put-role-policy --role-name AwsBroom --policy-name BroomScan --policy-document file://docs/iam/scan.json`。也可以直接用 AWS 托管的 `ReadOnlyAccess` 代替。 |
| **按服务分组** | 只允许清理特定服务，例如只清 EC2 + S3 | 每个分组一个文件 `iam/clean-<分组>.json`（见下表），都在 6144 字符以内，可作为托管策略创建后附加：`aws iam create-policy --policy-name BroomCleanEc2 --policy-document file://docs/iam/clean-ec2.json`，再 `aws iam attach-role-policy`。一个角色默认最多附加 10 个托管策略（可申请提到 20）。每个文件都已包含该分组的读取动作，不必再附加 scan.json。 |
| **全量清空** | 把整个 PoC 账号清空 | AWS 托管 `PowerUserAccess` 覆盖除 IAM 以外的全部分组；若还要清理 IAM 用户 / 角色 / 策略，再附加 `iam/clean-iam.json` 或直接使用 `AdministratorAccess`。 |

按服务分组的策略文件（分组与页面上的服务卡片一一对应）：

| 分组 | 文件 | 风险 | 默认勾选 | 备注 |
|---|---|---|---|---|
| EC2 | `clean-ec2.json` | 低 | 是 | 实例、ASG、EBS、快照、AMI、EIP、密钥对、Beanstalk |
| VPC | `clean-vpc.json` | 中 | 是 | VPC、子网、安全组、NAT/IGW、TGW、IPAM、Lattice、Network Firewall。清理 VPC 会顺带删除其依赖，因此动作最多 |
| 负载均衡 | `clean-load-balancing.json` | 低 | 是 | ELB / ALB / NLB |
| 容器 | `clean-containers.json` | 低 | 是 | ECS、EKS、ECR、App Runner |
| Serverless | `clean-serverless.json` | 低 | 是 | Lambda、API Gateway（IAM 动作是 `apigateway:GET` / `apigateway:DELETE`） |
| 数据库 | `clean-databases.json` | 中 | 是 | RDS / Aurora、DynamoDB、ElastiCache、Redshift、OpenSearch |
| 存储 | `clean-storage.json` | 中 | 是 | S3（含删除对象与所有版本）、EFS、AWS Backup |
| 消息 | `clean-messaging.json` | 低 | 是 | SQS、SNS、EventBridge、MQ、MSK、Kinesis、SES |
| 监控 | `clean-monitoring.json` | 低 | 是 | CloudWatch、CloudTrail、Prometheus、Grafana、Config |
| 开发工具 | `clean-devtools.json` | 低 | 是 | CloudFormation、CodeDeploy、DataSync、Cloud Map、RAM、SSM 参数 |
| 机器学习 | `clean-ml.json` | 低 | 是 | SageMaker |
| 安全 | `clean-security.json` | 高 | 否 | KMS（仅计划 7 天后删除）、Secrets Manager、ACM、GuardDuty、Security Hub、Macie |
| IAM | `clean-iam.json` | 高 | 否 | 用户、组、角色、策略、实例配置文件、OIDC 提供商。当前登录的 IAM 用户始终被排除 |
| 边缘与 DNS | `clean-edge-dns.json` | 高 | 否 | CloudFront、Route 53 |

所有策略的 `Resource` 都是 `"*"`：清理的本意就是覆盖账号内全部同类资源，按 ARN 收窄没有意义。想限制范围，请用**区域**条件，例如在角色上追加一条 Deny：

```json
{
  "Effect": "Deny",
  "Action": "*",
  "Resource": "*",
  "Condition": { "StringNotEquals": { "aws:RequestedRegion": ["ap-southeast-1", "us-east-1"] } }
}
```

请保留 `us-east-1`：IAM、CloudFront、Route 53 等全局服务的请求会记为该区域。S3、IAM 这类"全局"类型会使用你选择的第一个区域作为会话区域。

### 权限不足时的表现

- 登录返回 `AWS rejected the credentials`：缺少 `sts:GetCallerIdentity`，或凭证已过期。
- 区域列表为空并报错：缺少 `ec2:DescribeRegions`。
- 扫描页某类型显示错误、其余正常：该类型缺少读取动作。
- Review 页的 EC2 / VPC 资源显示"不可删除 · UnauthorizedOperation"：缺少对应的删除动作（Dry-run 检查失败），扫描本身不受影响。
- 清理时单个资源失败（AccessDenied）：只影响该资源，其他资源继续。失败列表会保留在结果里，补齐权限后可再次扫描并清理剩余项。

### 重新生成

```sh
make iam-policy     # 解析 go.mod 锁定的 cloud-nuke 源码，重写 docs/iam/
```

生成器会在以下情况报错退出，以便升级 cloud-nuke 时及时发现：出现未知的 SDK 服务、某个资源类型找不到客户端接口、某个分组策略超过 6144 字符。

## English

### What the tool does with your credentials

| Phase | Calls | Notes |
|---|---|---|
| Sign-in | `sts:GetCallerIdentity` | Validates the credentials and reads the account ID and ARN. Without it you cannot sign in. |
| Regions | `ec2:DescribeRegions` | Lists the regions enabled for the account. |
| Scan | `List*` / `Describe*` / `Get*` per service | Read-only. A resource type that is denied is reported as an error; the other types continue. |
| Scan (EC2 / VPC family) | delete calls with `DryRun=true` | cloud-nuke uses them to test whether you could delete the resource. Without the delete action the scan still succeeds, but those resources show as "not deletable". The 23 affected types are marked Dry-run in [`iam/actions.md`](iam/actions.md). |
| Scan with "only resources older than N hours" | `ec2:CreateTags`, `ecs:TagResource`, `es:AddTags`, `network-firewall:TagResource`, `sns:TagResource` | Writes a `cloud-nuke-first-seen` tag on resources that have no creation timestamp. No tags are written unless that option is on. |
| Clean | `Delete*` / `Terminate*` / `Detach*` etc. for the service | Only for resources you confirmed one by one on the Review page. |

The tool never creates resources, never changes your IAM policies (unless you select the IAM group and confirm deletion), never writes credentials to disk or logs, and never touches the instance metadata service or the host's `~/.aws`.

### Recommended setup: a dedicated role and one-hour STS credentials

1. In the **sandbox / PoC account**, create a role `AwsBroom` trusted by your own IAM user or SSO identity, MFA required, default `MaxSessionDuration` of one hour:

   ```json
   {
     "Version": "2012-10-17",
     "Statement": [{
       "Effect": "Allow",
       "Principal": { "AWS": "arn:aws:iam::123456789012:user/you" },
       "Action": "sts:AssumeRole",
       "Condition": { "Bool": { "aws:MultiFactorAuthPresent": "true" } }
     }]
   }
   ```

2. Attach one of the three tiers below.
3. Get temporary credentials and paste them into the page (the access key starts with `ASIA`; the session token is required):

   ```sh
   aws sts assume-role \
     --role-arn arn:aws:iam::123456789012:role/AwsBroom \
     --role-session-name broom \
     --duration-seconds 3600 \
     --query 'Credentials.[AccessKeyId,SecretAccessKey,SessionToken]' --output text
   ```

`aws sts get-session-token`, shown on the sign-in page, also works, but it inherits **all** of the IAM user's permissions and cannot narrow them, so the policy has to be attached to that user. Do not use long-lived access keys, and never use root credentials.

### Three permission tiers

| Tier | Purpose | How |
|---|---|---|
| **Read-only** | Scan and export an inventory, no cleanup | [`iam/scan.json`](iam/scan.json). At about 7,500 characters it exceeds the 6,144-character managed-policy limit, so attach it as an **inline** policy (role inline limit 10,240): `aws iam put-role-policy --role-name AwsBroom --policy-name BroomScan --policy-document file://docs/iam/scan.json`. The AWS-managed `ReadOnlyAccess` policy is an acceptable substitute. |
| **Per service group** | Allow cleanup of specific services only, e.g. EC2 + S3 | One file per group, `iam/clean-<group>.json` (table below), each under 6,144 characters, so it can be a managed policy: `aws iam create-policy --policy-name BroomCleanEc2 --policy-document file://docs/iam/clean-ec2.json`, then `aws iam attach-role-policy`. A role takes 10 managed policies by default (raisable to 20). Each file already includes the group's read actions; scan.json is not needed on top. |
| **Full wipe** | Empty a whole PoC account | The AWS-managed `PowerUserAccess` covers every group except IAM. Add `iam/clean-iam.json` if you also want to delete IAM users, roles and policies, or simply use `AdministratorAccess`. |

Per-group policy files (groups match the service cards in the UI):

| Group | File | Risk | Selected by default | Notes |
|---|---|---|---|---|
| EC2 | `clean-ec2.json` | low | yes | instances, ASG, EBS, snapshots, AMIs, EIPs, key pairs, Beanstalk |
| VPC | `clean-vpc.json` | medium | yes | VPCs, subnets, security groups, NAT/IGW, TGW, IPAM, Lattice, Network Firewall. Deleting a VPC also removes its dependencies, hence the largest action list |
| Load balancing | `clean-load-balancing.json` | low | yes | ELB / ALB / NLB |
| Containers | `clean-containers.json` | low | yes | ECS, EKS, ECR, App Runner |
| Serverless | `clean-serverless.json` | low | yes | Lambda, API Gateway (IAM actions are `apigateway:GET` / `apigateway:DELETE`) |
| Databases | `clean-databases.json` | medium | yes | RDS / Aurora, DynamoDB, ElastiCache, Redshift, OpenSearch |
| Storage | `clean-storage.json` | medium | yes | S3 (including objects and all versions), EFS, AWS Backup |
| Messaging | `clean-messaging.json` | low | yes | SQS, SNS, EventBridge, MQ, MSK, Kinesis, SES |
| Monitoring | `clean-monitoring.json` | low | yes | CloudWatch, CloudTrail, Prometheus, Grafana, Config |
| Dev tools | `clean-devtools.json` | low | yes | CloudFormation, CodeDeploy, DataSync, Cloud Map, RAM, SSM parameters |
| Machine learning | `clean-ml.json` | low | yes | SageMaker |
| Security | `clean-security.json` | high | no | KMS (7-day scheduled deletion only), Secrets Manager, ACM, GuardDuty, Security Hub, Macie |
| IAM | `clean-iam.json` | high | no | users, groups, roles, policies, instance profiles, OIDC providers. The signed-in IAM user is always excluded |
| Edge & DNS | `clean-edge-dns.json` | high | no | CloudFront, Route 53 |

Every policy uses `"Resource": "*"`: cleanup is meant to cover all resources of a kind in the account, so narrowing by ARN makes no sense. To limit the blast radius use a **region** condition instead, for example an extra Deny on the role:

```json
{
  "Effect": "Deny",
  "Action": "*",
  "Resource": "*",
  "Condition": { "StringNotEquals": { "aws:RequestedRegion": ["ap-southeast-1", "us-east-1"] } }
}
```

Keep `us-east-1` in the list: requests to global services such as IAM, CloudFront and Route 53 are attributed to it. "Global" types like S3 and IAM use the first region you selected as their session region.

### What missing permissions look like

- Sign-in fails with `AWS rejected the credentials`: `sts:GetCallerIdentity` is missing, or the credentials expired.
- The region list is empty with an error: `ec2:DescribeRegions` is missing.
- One type shows an error on the scan page while the others work: that type's read actions are missing.
- EC2 / VPC resources on the Review page show "not deletable · UnauthorizedOperation": the matching delete action is missing (the dry-run check failed). The scan itself is unaffected.
- A single resource fails with AccessDenied during cleanup: only that resource is affected. Failures stay in the result; grant the permission and run "scan again" to clean up what is left.

### Regenerating

```sh
make iam-policy     # parses the cloud-nuke sources pinned in go.mod and rewrites docs/iam/
```

The generator exits with an error when it meets an unknown SDK service, a resource type without a client interface, or a group policy above 6,144 characters, so a cloud-nuke upgrade cannot silently leave the docs stale.
